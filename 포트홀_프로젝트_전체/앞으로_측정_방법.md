# 앞으로 측정 방법 (기말 12/10까지)

기말 평가: **완성도 40 / 사업성 20 / 발표 40**. 발표는 PPT 말고 **실물·동영상·시뮬레이션**을 쓰는지, 10분 안에 짜임새 있게 하는지를 본다 (스크립트 읽으면 감점).
그래서 측정 목표는 세 가지다.
1. **실물이 실제로 이어서 돌아가는 장면** (센서 → 사진 → 서버 → 지도) 을 영상으로 남기기
2. **오감지를 AI가 얼마나 거르는지** 숫자 하나 만들기
3. 발표 때 보여줄 **실물 케이스**

---

## 0단계. 매번 측정 전 점검 (5분)

```
cd ~/포트홀_프로젝트_전체_20261118/03_라즈베리파이
python3 check_all.py 0
```
- 전원: "저전압 없음"이어야 함 (`vcgencmd get_throttled` 가 0x0, 과거 기록만 있으면 0x50000은 괜찮음)
- 센서: ADXL345 0x53 잡히는지
- 저장공간, 시간(폰 시간과 몇 초 차이인지)

**폰 시간과 파이 시간이 맞아야 위치를 붙일 수 있다.** 파이를 인터넷에 한 번 붙여 시간 동기화하고 시작.

## 1단계. 책상 위 통합 테스트 (실내, 1시간)

차에 타기 전에 집이나 실습실에서 전체 흐름이 이어지는지 먼저 본다.

### 1-1. A형 (커넥티드형)
1. Supabase에 `shock_events` 테이블이 있는지 확인 (`11_서버_Supabase/테스트용_SQL.sql` ②)
2. 파이: `python3 pi_blackbox_sim.py key --phone` (파이가 인터넷에 연결된 상태)
3. 폰 테스트 앱: 서버 설정 → **라즈베리파이 센서 사용** 체크 → 측정 시작
4. 파이에서 Enter 3번 → 폰에 기록 3개 → 팀 지도에 핀 3개
5. **화면 녹화** (폰) + **파이 터미널 촬영** → 발표 영상 재료

### 1-2. B형 (스마트폰 연동형) + 와이파이·LTE 분리
1. 폰 와이파이 설정에서 `PotholeCam` 이 저장돼 있으면 **삭제** (주 와이파이로 잡히는 것 방지), 모바일 데이터 켜기
2. 파이: 와이파이 핫스팟 켜고 `python3 pi_blackbox_sim.py key --serve` (자동 스크립트는 PI_TASK.md 4단계)
3. 폰 테스트 앱: **B형** 체크 → **블랙박스 등록·연결** → 처음 뜨는 창에서 연결 허용 → 측정 시작
4. 파이에서 Enter → 폰에 기록이 뜨고 **바로 "업로드 다 됨"** 이 나오면 성공
5. 확인해서 기록할 것:
   - 업로드까지 걸린 시간 (Enter부터 지도 핀까지 몇 초)
   - 상단바 아이콘 (와이파이 + LTE 같이 뜨는지) 캡처
   - 실패하면 화면 문구 캡처

| 기록표 | 1회 | 2회 | 3회 |
|---|---|---|---|
| A형: Enter → 지도 핀 (초) | | | |
| B형: Enter → 폰 수신 (초) | | | |
| B형: 폰 수신 → 업로드 완료 (초) | | | |

## 2단계. 실차 측정 (케이스 넣고, 30분)

### 준비
- 케이스(v3c)에 파이·배터리·센서 넣고 폰 끼우기. **센서가 홈에 단단히 끼워졌는지** 확인 (흔들리면 값이 달라짐)
- **블랙박스**(S23을 끼운 케이스)를 차량 거치대에 고정, S23 카메라가 앞 도로를 보게
- **운전자 폰**은 따로: 포트홀 알리미(또는 테스트) 앱 켜고 위치·모바일 데이터 ON → GPS 위치와 업로드 담당
- 파이 ↔ S23 USB 연결 시 **파이 전원 부족 여부** 확인 (S23이 충전을 빼가면 파이가 느려지거나 꺼질 수 있음 → S23 배터리 80% 이상으로 시작)
- S23을 카메라로 쓰려면 파이에서 S23 화면(USB 웹캠 모드)을 찍는 코드가 먼저 필요함. 없으면 이번 측정은 테스트 앱의 폰 카메라로 대신

### 2-1. 케이스 넣은 상태로 캘리브레이션 다시 하기 (권장)
센서 붙이는 위치가 바뀌면 기준값이 달라질 수 있다.
```
python3 calibrate.py normal 600    # 10분 평소 주행, 방지턱 지날 때마다 Enter
python3 calibrate.py result
```
- 지난번과 같은 **교내 방지턱 코스, 7공학관 출발 시계 방향**으로 돌면 비교가 쉽다
- 결과를 지난번(13개 중 11개, 오감지 14번)과 비교 → 케이스 영향 확인

### 2-2. 실제 감지 + 사진 업로드
지금 바로 쓸 수 있는 방법은 두 가지다.
- **폰 센서로 전체 흐름 (바로 가능)**: 테스트 앱에서 "감지하면 potholes에 올리기 + 5초마다 gps_logs + 사진" 체크 → 측정 시작. 폰 가속도로 SDK와 같은 계산을 해서 사진·위치까지 올린다.
- **파이 센서로 기록 (바로 가능)**: `python3 calibrate.py normal` 로 센서 값만 기록하고, 끝나고 `pi_blackbox_sim.py replay <기록.csv> --only-bumps` 로 지도에 올린다.

**파이 실제 센서 → 바로 서버 업로드**를 한 번에 하는 모드는 아직 없다 (`pi_blackbox_sim.py` 는 Enter·재생만, `pothole_detect.py` 는 서버 없이 폴더 저장). 발표 시연에 필요하면 차에 타기 전에 이 모드를 먼저 추가해야 한다.

주행 중에는 손대지 말고, 끝나고 지도에 찍힌 핀과 사진을 확인한다.

### 2-3. 우드락 포트홀 (교수님 권장)
- 우드락으로 포트홀 모형(움푹 들어간 판)을 만들어 주차장 같은 안전한 곳에서 천천히 통과
- 감지 → 사진 → 지도 핀이 뜨는 장면을 **바깥에서 한 명이 찍고, 폰 화면도 녹화**
- 이게 발표의 "실물 시연 영상"이 된다

## 3단계. AI로 오감지 거르기 (숫자 만들기)

목표 문장: **"센서만 쓰면 오감지 14번 → 사진 확인 후 N번"**

1. 2단계에서 올라온 사진(감지 순간 사진)을 모은다. 방지턱/포트홀 사진과 그냥 도로 사진(오감지)이 섞여 있음
2. 사람이 먼저 정답 표를 만든다: 사진마다 "진짜(방지턱·포트홀)" / "오감지"
3. YOLO26n 학습 모델(05_AI_YOLO)로 같은 사진을 돌린다 (라즈베리파이 4 또는 노트북)
4. 표로 정리:

| | 사람 정답: 진짜 | 사람 정답: 오감지 |
|---|---|---|
| YOLO: 포트홀/방지턱 있음 | 맞게 남김 | **못 거른 것** |
| YOLO: 없음 | **놓친 것** | 맞게 거름 |

5. 발표용 숫자: "오감지 ○번 중 ○번 제거, 진짜는 ○개 중 ○개 유지"

주의: 우리 YOLO는 **포트홀·맨홀**을 배웠고 방지턱은 따로 안 배웠다. 교내 코스는 방지턱이라 "방지턱도 진짜로 볼지" 기준을 먼저 정해야 한다. 가능하면 우드락 포트홀이나 실제 포트홀 사진으로 평가하는 게 깔끔하다.

## 측정할 때 자주 생기는 문제

| 증상 | 원인 / 해결 |
|---|---|
| 파이가 계속 재부팅 | 전원 문제. 충전된 18650인지, 짧은 선인지 확인 (EEPROM 설정은 이미 함) |
| 감지가 너무 많음 | 센서가 헐거움 → 홈에 테이프 한 겹, 또는 캘리브레이션 다시 |
| 감지가 너무 적음 | 기준값이 높음 → `threshold.json` 확인, 0.20g 근처 |
| 사진 ✗ | Supabase 사진 버킷 정책 (11_서버_Supabase SQL ①) |
| B형 "업로드 대기"만 계속 | 폰이 PotholeCam을 주 와이파이로 잡음 → 와이파이 설정에서 삭제 후 앱으로 다시 연결 |
| 위치가 이상한 데 찍힘 | 폰·파이 시간 차이 → 0단계 시간 맞추기 |
| 지도에 핀이 안 뜸 | 앱과 같은 Supabase 프로젝트(`dwejbbhrjfcqcnslheas`)인지 확인 |
