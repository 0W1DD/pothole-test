# 자전거 포트홀 감지 MATLAB 시뮬레이션

MATLAB + Simulink 로 돌아가요 (R2020a 이상 추천, 한글 깨짐 방지). 다른 툴박스는 필요 없어요.
폴더째로 MATLAB 현재 폴더로 열고 `step1 → step2 → step3` 순서로 실행하면 돼요.
결과 그림과 표는 `results/` 폴더에 저장돼요.

## Simulink 모델

`bike_pothole_model.slx` 가 진동 계산의 본체예요. 처음 `step1_demo.m` 을 실행하면
`build_bike_model.m` 이 모델을 블록 단위로 자동으로 그려서 저장하고, 다음부터는 그 파일을 써요.
따로 만들고 싶으면 명령 창에 `build_bike_model(true)` 를 입력하면 돼요 (직접 고친 내용은 덮어써져요).

```
노면(From Workspace) ─┬→ Front_wheel ─→ ×wf ──┐
                      └→ Rear_wheel  ─→ ×(1-wf)┴→ ÷9.81 → ADXL345(400Hz, 잡음, 분해능, ±16g)
   → 충격 ||a+1|-1| → 충격 점수(WINDOW 평균 FIR) → detector(기준값 + 쿨다운) → Scope / To Workspace
```

- `Front_wheel`, `Rear_wheel` 서브시스템을 더블클릭하면 운동방정식을 적분기·게인으로 그린 블록도가 나와요.
- 블록 값은 변수 이름(kt, m1, wf, th …)으로 들어가 있고, `run_simulink_model.m` 이 실행 직전에 채워 넣어요.
  숫자를 바꿀 땐 `bike_params.m` 만 고치면 돼요.
- 3단계는 Simulink를 30번 실행해서 시간이 좀 걸려요. 빠르게 돌리고 싶으면 `bike_params.m` 에서
  `p.use_simulink = false` 로 바꾸면 같은 식을 MATLAB 코드로 계산해요.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `step1_demo.m` | 시뮬레이션 데모: 60초 주행 중 방지턱 2개, 포트홀 1개 → 센서 값·충격 점수·감지 결과 그래프 |
| `step2_compare_real.m` | 실측 비교: 실제 자전거 데이터로 모델을 맞추고(보정), 방지턱 데이터로 맞는지 확인(검증) |
| `step3_tune_threshold.m` | 신뢰성 + 기준값 고르기: 무작위 주행 30번 → 감지율·오감지 → 추천 THRESHOLD, WINDOW |
| `build_bike_model.m` | Simulink 모델 `bike_pothole_model.slx` 자동 생성 |
| `run_simulink_model.m` | 변수 넣고 Simulink 실행, 결과 꺼내기 |
| `bike_params.m` | 모델 숫자 모음 (질량, 타이어, 속도, 센서 설정). 바꿀 땐 여기만 |
| 나머지 `.m` | 노면 만들기, 주행 계산, 감지 규칙 등 부품 |

## 모델

바퀴 하나를 2자유도(자전거+바퀴 / 사람)로 보고, 앞바퀴와 뒷바퀴를 따로 계산해서 섞어요.
뒷바퀴는 축거(1.05 m)만큼 늦게 같은 노면을 지나서 방지턱에서 충격이 두 번 생겨요.

```
   [ 사람 m2 ]
      |  kr, cr    팔다리
   [ 자전거 m1 ]  ← 센서
      |  kt, ct    타이어
 ~~~~ 노면 ~~~~    ISO 8608 거칠기 + 방지턱/포트홀
```

센서 쪽은 파이썬 코드와 똑같이 맞췄어요: 400 Hz, ±16g, 분해능 3.9 mg,
충격 = |가속도 크기 − 1g|, 충격 점수 = WINDOW초 평균, 감지 후 COOLDOWN 2초.

## 실측 데이터 넣는 법 (2단계)

1. 자전거에서 `calibrate.py normal`, `calibrate.py bump` 로 기록
2. 파이의 `calib_normal.csv`, `calib_bump.csv` 를 이 폴더의 `data/` 에 복사
3. `step2_compare_real.m` 위쪽에 기록할 때 정보 입력
   - `V_REAL` 평균 속도 (m/s) — 폰 속도계 앱이나 GPS로 확인
   - `BUMP_H`, `BUMP_L` 방지턱 높이·길이 — 자로 재기
   - `BUMP_COUNT` 넘은 횟수

CSV가 없으면 **예시 데이터**로 돌아가고, 그래프 제목에 "(예시 데이터)"라고 표시돼요.
교수님께 틀을 먼저 보여 드릴 때 이 상태로 써도 돼요.

## 신뢰성을 말하는 방법

- **보정**: 평소 주행 데이터 하나(충격 점수 중간값)만으로 노면 거칠기를 맞춤
- **검증**: 보정에 안 쓴 방지턱 데이터와 비교 → 방지턱 최고값 오차, 스펙트럼 일치도(r)
- 보정에 안 쓴 데이터까지 맞으면 "모델이 실제 자전거를 잘 흉내 낸다"고 말할 수 있고,
  그 모델로 3단계에서 여러 상황(속도, 노면, 장애물 크기)을 시험한 결과를 믿을 수 있어요.

## 3단계 결과를 파이에 쓰는 법

출력되는 `WINDOW`, `THRESHOLD` 를 `calibrate.py` 와 `pothole_detect.py` 에 넣어 비교해 보세요.
최종 값은 실제 주행으로 만든 `threshold.json` 이 우선이고, 시뮬레이션 값은
"이 근처면 안전하다"는 범위를 알려 주는 용도예요.

## 발표 순서 예시

1. 목적: 충격 센서로 포트홀을 감지할 때 기준값을 어떻게 정하고, 얼마나 믿을 수 있나
2. 모델 그림 (위 2자유도 그림) + 센서 설정
3. 1단계 그림: 평소 주행과 방지턱/포트홀 충격 차이, 앞뒤 바퀴 두 번 충격
4. 2단계 표·그림: 실측 vs 시뮬레이션 오차 → 모델 신뢰성
5. 3단계 그림: 감지율 vs 오감지, 추천 기준값, 속도별 감지율
6. 한계: 세로 방향만 계산, 사람 몸은 단순 스프링, 센서 고정 방식에 따라 달라짐
