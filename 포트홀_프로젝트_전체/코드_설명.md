# 코드 설명 (폴더별)

처음 보는 사람도 "이 파일이 뭐 하는 건지, 어떻게 돌리는지" 알 수 있게 정리했다.

> **역할 구분**: 갤럭시 S23 = 블랙박스 카메라 역할만 (파이와 USB). 운전자 스마트폰 = 포트홀 알리미 앱 (GPS 위치 + 업로드 + 지도).
> 단, 02 테스트 앱은 실험용이라 폰 한 대가 카메라와 GPS를 둘 다 맡는다.

## 01_앱_최종: 포트홀 알리미 (최종 앱)

- **설치**: `포트홀알리미_v1.0.3-test.apk` (최신, 테스트용 가짜 포트홀이 서울시청 근처에 보임) 또는 `포트홀알리미_v1.0.2.apk` 를 폰에 복사해서 설치 (출처를 알 수 없는 앱 허용). 앱 ID `com.gimmegimme.pothole`, 안드로이드 7 이상 (블랙박스 연결은 10 이상)
- **만든 방식**: 웹(HTML/JS/CSS) 화면을 Capacitor 8로 안드로이드 앱으로 감쌌다. 와이파이 제어·주변 알림처럼 웹으로 안 되는 기능만 Java로 따로 만들었다.

### 화면 (아래 탭 4개)
| 탭 | 기능 |
|---|---|
| 지도 | 카카오 지도에 포트홀 핀 (빨강 발견 / 파랑 수리중), 핀 누르면 사진·크기·주소(복사), 내 위치, 주소 검색, 차 위치(gps_logs) |
| 게시판 | 배상청구 후기 커뮤니티: 카카오 로그인, 글·사진·댓글, 본인 글만 수정·삭제 |
| 배상청구 | 사고 위치 입력 → 도로 등급별 관할 기관 청구 방법 + 필요 서류 체크리스트(진행률) |
| 내정보 | 프로필, **블랙박스 연결**, **주변 포트홀 안내** |

### 소스 구조 (`소스코드/`)
| 파일 | 하는 일 |
|---|---|
| `www/index.html`, `www/style.css` | 화면 전체 |
| `www/app.js` | 지도, 로그인, 게시판, 배상청구 로직. 맨 위에 Supabase 주소·공개 키 |
| `www/blackbox-wifi.js` | 블랙박스 와이파이 연결을 웹에서 부르는 함수 (`BlackboxWifi.register/connect/getJson/getPhoto…`) |
| `www/nearby-alerts.js`, `www/nearby-alert-config.json` | 주변 포트홀 안내 설정 화면, 서버 주소 |
| `android/.../BlackboxWifiPlugin.java` | **와이파이·LTE 분리 핵심**. 안드로이드 10+ Wi-Fi Network Request로 블랙박스에만 붙고, 인터넷은 LTE 유지. 처음 한 번 허용 후 SSID+BSSID로 자동 재연결 |
| `android/.../BlackboxHttpPolicy.java`, `BlackboxCredentials.java` | 블랙박스 주소만 접속 허용, 등록 정보 저장 |
| `android/.../NearbyAlertService.java` | 화면 꺼져도 도는 위치 서비스: 반경 안 포트홀을 알림 + 한국어 음성 |
| `android/.../NearbyAlertPolicy.java` | 거리 계산, 같은 포트홀 10분간 반복 금지 등 |
| `tests/blackbox/` | 정책 테스트 (Java 17개, JS 7개 통과 기록) |
| `../문서/` | BLACKBOX_WIFI.md, NEARBY_ALERTS.md, UPDATE-20261112.md: 기능별 상세 |

### 다시 빌드하는 법
```
cd 소스코드
npm install
npx cap sync android          # www 를 android 안으로 복사
cd android && ./gradlew assembleDebug
```
(또는 안드로이드 스튜디오로 `android` 폴더 열고 ▶ Run). 버전은 `android/app/build.gradle` 의 versionCode 4 / versionName 1.0.3-test.
소스는 GitHub에 올라온 11/13 소스에, 1.0.3-test APK의 웹 파일(app.js·index.html)을 합쳐 복원한 것이다 (1.0.2의 프로필 수정 포함). 안드로이드 코드는 APK와 같은 것을 확인했다.
**테스트 가짜 포트홀 끄기**: `www/app.js` 의 `USE_TEST_POTHOLES = true` → `false`.

### 주의
- 최종 앱의 블랙박스 기능은 **기록·사진 받기까지**. 서버 자동 업로드는 02 테스트 앱에만 있다.
- 지도는 카카오 지도 SDK 도메인 등록이 필요하다 (앱은 `https://localhost`).

## 03_라즈베리파이: 파이 코드

파이에 이 폴더(와 04 SDK 폴더)를 복사해서 쓴다. 처음 한 번 `bash setup.sh`.

| 파일 | 하는 일 | 실행 |
|---|---|---|
| `check_all.py` | **측정 전 점검**: 전원(저전압), 센서, GPS, 카메라, 저장공간 | `python3 check_all.py` (GPS 대기 생략은 `0`) |
| `calibrate.py` | **캘리브레이션**: 평소 주행/방지턱을 기록해 기준값 계산 → `threshold.json` | `python3 calibrate.py normal` → `bump` → `result` |
| `pi_blackbox_sim.py` | **블랙박스 흉내** (센서·카메라 없어도 됨). SDK로 판단 → 사진·위치 → 서버 | 아래 표 |
| `pothole.py` | SDK 파이썬 연결 (C 라이브러리 없으면 같은 결과의 순수 파이썬) | import 용 |
| `pothole_detect.py` | 자전거 단계 감지 + YOLO (서버 없이 폴더에 분류 저장) | `python3 pothole_detect.py` |
| `gps_upload_팀웹용.py` | USB GPS 위치를 5초마다 `gps_logs`로 (TEST_MODE=True면 가짜 위치) | GPS 잡히면 False로 |
| `tidy_pi.py` | 파이 홈 폴더 정리 (지우지 않고 옮기기만) | |
| `setup.sh` | 패키지 설치 + SDK 빌드 + 점검 한 번에 | `bash setup.sh` |
| `PI_TASK.md` | 파이에 깔린 Claude Code에게 주는 A형·B형 테스트 지시서 | |

### pi_blackbox_sim.py 모드
| 명령 | 뜻 |
|---|---|
| `python3 pi_blackbox_sim.py key` | Enter 칠 때마다 가짜 충격 → potholes에 바로 올림 |
| `... key --phone` | **A형**: 충격 신호만 `shock_events`로. 사진·GPS는 폰 앱이 붙임 |
| `... key --serve` | **B형**: 파이 안(`b_store/`)에만 저장, 8080 포트로 폰에 제공 |
| `... replay ../07_실차측정데이터/calib_normal.csv --dry` | 실차 기록으로 판별만 (13개 중 11개 나와야 정상) |
| `... replay ... --only-bumps` | 방지턱 근처 감지만 지도에 올림 |

서버 정보는 같은 폴더의 `server.json` 에 둔다 (zip에는 없음, 직접 만들기):
```json
{"url": "https://dwejbbhrjfcqcnslheas.supabase.co", "key": "sb_publishable_..."}
```

B형 파이 와이파이 켜기/끄기:
```
sudo nmcli device wifi hotspot ifname wlan0 ssid PotholeCam password pothole1234
sudo nmcli connection down Hotspot
```
(켜면 SSH가 끊기니 모니터+키보드, 또는 PI_TASK.md의 자동 스크립트 사용)

## 04_충격감지_SDK_C: 핵심 기술

| 파일 | 하는 일 |
|---|---|
| `include/pothole.h`, `src/pothole.c` | SDK 본체. C99, 정수만, malloc 없음, 고정 링버퍼 |
| `python/pothole.py` | 파이썬 연결 |
| `examples/csv_demo.c`, `pi_adxl.py` | 사용 예시 (CSV 재생, 실제 센서) |
| `tests/test_sdk.py` | C와 파이썬 결과가 같은지 검사 |
| `tests/bench*.c`, `bench_pi.py` | 속도 측정 |
| `Makefile` | `make` 로 빌드 → `build/libpothole.so` |

사용 순서 (블랙박스 회사가 쓰는 방식):
```c
pd_config c; pd_default_config(&c);   // 기준 300mg(실차 권장 200), 창 20, 쿨다운 2000ms, 최소속도 10km/h
pd_detector d; pd_init(&d, &c);
// 센서 샘플마다
if (pd_feed(&d, t_ms, x_mg, y_mg, z_mg, &ev) == PD_EVENT) {
    // ev.score_mg, ev.photo_back_ms (몇 ms 전 프레임을 보낼지)
}
```
SDK는 **판단만** 한다. 사진 촬영·전송은 블랙박스 회사의 기존 기능을 쓰고, YOLO는 SDK에 없다(서버나 앱에서 실행).

## 05_AI_YOLO
`pothole_yolo_train.ipynb`: Colab에서 실행. Roboflow 포트홀 데이터(11,763장, Pothole·Manhole) + COCO를 섞어 YOLO26n을 60 epoch 재학습. NCNN(파이용), TFLite int8(칩용, 미검증) 내보내기.
주의: Ultralytics YOLO는 AGPL-3.0 → 상용화 땐 기업 라이선스나 다른 모델 필요.
